# Development Plan

이 문서는 `오늘 뭐입지? - Daily Outfit Weather`의 구현 순서를 정리한 개발 작업 기준 문서입니다.

## ⚠️ 필수 개발 트리거: 사전 영향도 분석 (Pre-Implementation Trigger)

**모든 Phase 및 신규 기능/변경 작업 개시 전 필수 지침:**
- 개발자 및 AI 에이전트는 **기능 코드 작성을 시작하기 직전, 반드시 [`docs/impact-analysis-guide.md`](./impact-analysis-guide.md)를 확인(`view_file`)**해야 합니다.
- 7대 사전 영향도 검토 영역(DB 역직렬화, 계산 엔진, API 계약, 인증/세션, 프론트 UI, 외부 API, 배포 환경)에 대해 영향도를 평가하고 예방 대책을 수립한 후에만 코드 작성을 진행합니다.
- 기능 구현 완료 후에는 서브에이전트(Subagent)를 실행하여 사전 영향도 평가 결과와 구현체의 정합성을 최종 검수받아야 합니다.

## 구현 전 결정 사항

### 프로젝트 이름

- 폴더/레포명: `daily-outfit-weather`
- 서비스명: `오늘 뭐입지?`
- 영문 표기: `Daily Outfit Weather`

기존 기획 문서에는 `weather-fit` 이름이 섞여 있었지만, 현재 GitHub 주소와 폴더명을 기준으로 구현 레포명은 `daily-outfit-weather`로 통일합니다.

### 아키텍처 기준

- MVP는 Modular Monolith로 구현합니다.
- 백엔드는 하나의 Spring Boot 애플리케이션입니다.
- 내부 패키지는 도메인별 모듈로 분리합니다.
- 각 모듈 내부는 Layered Architecture를 따릅니다.
- MSA 분리는 후순위 확장 전략으로만 고려합니다.

### MVP 축소 기준

원본 기획서의 MVP 범위는 포트폴리오 프로젝트 기준으로는 좋지만 첫 구현 단위로는 큽니다. 따라서 구현은 다음 순서로 나눕니다.

1. 인증 없이 로컬/더미 사용자 기준 추천 흐름 구현
2. 사용자/프로필/위치 도메인 구현
3. 추천 엔진과 오늘 추천 API 구현
4. 실제 기상청 API 연결
5. 프론트엔드 MVP 화면 구현
6. 실제 Google OAuth 연결
7. 알림 로그 및 PWA 설정 확장

## Phase 1. 프로젝트 초기 세팅

목표:

- 백엔드/프론트 프로젝트 골격 생성
- 로컬 실행 환경 구성
- Harness Kit 기준 문서 구조 정리

작업:

- `backend` Spring Boot 프로젝트 생성
- `frontend` React + Vite 프로젝트 생성
- `docker-compose.yml`로 PostgreSQL 구성
- `.env.example` 작성
- 기본 패키지 구조 생성
- 실행 명령 문서화

완료 기준:

- 백엔드 애플리케이션이 로컬에서 실행된다.
- 프론트엔드 애플리케이션이 로컬에서 실행된다.
- PostgreSQL 컨테이너가 로컬에서 실행된다.
- README에 실행 방법이 추가된다.

## Phase 2. 사용자/프로필/위치 기본 도메인

목표:

- 추천 생성을 위한 사용자 설정을 저장할 수 있다.

작업:

- User 도메인 생성
- UserProfile 도메인 생성
- Location 도메인 생성
- 온보딩 저장 API 구현
- 프로필 조회/수정 API 구현
- 위치 입력은 MVP에서 동 단위 수동 입력으로 시작

완료 기준:

- 온보딩 API로 사용자 설정을 저장할 수 있다.
- 프로필 조회 API로 저장된 설정을 확인할 수 있다.
- 사용자당 집/직장 위치를 구분해 저장할 수 있다.

## Phase 3. 추천 엔진 1차 구현

목표:

- 실제 외부 API 없이도 룰 기반 옷차림 추천을 생성할 수 있다.

작업:

- 추천 입력 DTO 정의
- WeatherConditionAnalyzer 구현
- RecommendationRuleEngine 구현
- OutfitSelector 구현
- ItemSelector 구현
- RecommendationMessageGenerator 구현
- 단위 테스트 작성

완료 기준:

- 체감 기준 온도에 따라 옷차림 추천이 달라진다.
- 강수확률/강수유형에 따라 우산 추천이 달라진다.
- 말투 설정에 따라 추천 문구가 달라진다.

## Phase 4. 오늘 추천 API

목표:

- 사용자가 오늘 추천 결과를 조회할 수 있다.

작업:

- OutfitRecommendation 도메인 생성
- 오늘 추천 생성 API 구현
- 오늘 추천 조회 API 구현
- 같은 사용자/날짜의 추천 중복 생성 방지
- 추천 결과 저장

완료 기준:

- 오늘 추천이 없으면 생성 후 반환한다.
- 오늘 추천이 있으면 기존 결과를 반환한다.
- 추천 생성 근거가 저장된다.

## Phase 5. 날씨 API 연동

목표:

- 기상청 단기예보 API를 이용해 출근/퇴근 시간대 날씨를 가져온다.

작업:

- WeatherApiClient 구현
- 동 단위 위치와 예보 좌표 매핑 방식 결정
- 기상청 응답 파싱
- 출근/퇴근 시간대 예보 추출
- WeatherForecast 저장

주의:

- 기상청 단기예보 API에서 바로 제공하지 않는 값은 MVP에서 계산 또는 제외한다.
- 체감온도는 자체 계산값으로 다룬다.
- 미세먼지와 자외선은 별도 API가 필요하므로 1차 구현에서는 제외하거나 더미 필드로 둔다.

## Phase 6. 프론트엔드 MVP 화면

목표:

- 모바일 기준으로 오늘 추천을 확인할 수 있다.

작업:

- 로그인 화면 골격
- 온보딩 화면
- 오늘 추천 화면
- 피드백 입력 UI
- 설정 화면
- API 클라이언트 구성

완료 기준:

- 사용자가 온보딩 정보를 입력할 수 있다.
- 오늘 추천 결과를 확인할 수 있다.
- 추천 피드백을 남길 수 있다.

## Phase 7. 인증 연동

목표:

- Google OAuth 기반 로그인 흐름을 연결한다.

작업:

- Spring Security 설정
- Google OAuth 클라이언트 설정
- 로그인 성공 후 사용자 저장
- `/api/me` 구현
- 프론트 로그인 버튼 연결

인증 방식:

- MVP는 Session Cookie 기반 OAuth로 시작한다.
- JWT는 추후 배포 구조가 분리되거나 모바일 앱 확장이 필요할 때 재검토한다.

## Phase 8. 피드백/알림 로그

목표:

- 추천 피드백과 알림 로그를 저장한다.

작업:

- Feedback 도메인 생성
- 피드백 등록 API 구현
- NotificationLog 도메인 생성
- 아침 알림 대상 조회 로직 구현
- 실제 발송 없이 알림 로그만 생성

완료 기준:

- 추천에 대한 피드백을 저장할 수 있다.
- 특정 시간 기준 알림 대상자를 조회하고 알림 로그를 생성할 수 있다.

## Phase 9. PWA 기본 설정

목표:

- 모바일 홈 화면에서 앱처럼 실행할 수 있는 기반을 만든다.

작업:

- manifest 설정
- 앱 이름/아이콘/theme color 설정
- service worker 기본 설정
- 모바일 화면 검수

완료 기준:

- 브라우저에서 PWA 설치 조건을 만족한다.
- 모바일 크기에서 주요 화면이 깨지지 않는다.

## 후순위 기능

- 피드백 기반 개인화 보정
- 가족 프로필
- 컨디션 기능
- 생리주기 선택 기능
- 캐릭터 커스터마이징
- 결제/구독
