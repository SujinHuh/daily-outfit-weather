# Notification Policy

알림 정책과 스케줄링 구조를 정리한 문서입니다.

## MVP 1차 알림 범위

MVP 1차에서는 실제 푸시를 보내지 않습니다.

구현 범위:

- 앱 내 오늘 추천 화면
- 알림 발송 대상 생성
- 알림 로그 저장

제외 범위:

- 실제 웹 푸시 발송
- FCM 연동
- 브라우저 알림 권한 요청
- 푸시 구독 정보 저장
- 날씨 변경 감지에 따른 실제 변경 알림 생성

단, `changeAlertOption` 설정값은 사용자 프로필에 미리 저장할 수 있습니다.

## 알림 종류

### 아침 정기 알림

사용자가 설정한 시간에 하루 1회 생성됩니다.

예시:

```text
오늘은 바람 때문에 쌀쌀해요. 얇은 외투 챙겨주세요~
```

### 날씨 변경 알림

아침 정기 알림 이후 날씨 예보가 변경되었을 때, 사용자의 행동 변화가 필요한 경우에만 생성합니다.

이 기능은 MVP 1.5 또는 2차에서 구현합니다. MVP 1차에서는 설정값만 저장하고 실제 변경 알림은 생성하지 않습니다.

예시:

```text
퇴근 시간 예보가 바뀌었어요.
비가 올 가능성이 높아져서 작은 우산을 챙기는 게 좋아요.
```

## 변경 알림 발송 조건

변경 알림은 단순한 수치 변화가 아니라 추천 결과가 바뀌는 경우에만 발송합니다.

- 비 안 옴 → 비 옴
- 우산 불필요 → 우산 필요
- 외투 불필요 → 외투 필요
- 퇴근길 기온 급락
- 강풍주의 수준으로 변경
- 눈 예보 추가

후순위 조건:

- 미세먼지 매우 나쁨으로 변경

## 변경 알림 제한

- 정기 알림: 하루 1회
- 변경 알림: 하루 최대 1회

## 변경 알림 설정 옵션

- 중요할 때만
- 비/눈만
- 받지 않기

## 알림 문구 정책

날씨 예보 변경 시 "정정"이 아니라 "업데이트"로 표현합니다.

좋은 예:

```text
퇴근 시간 예보가 바뀌었어요.
비가 올 가능성이 높아졌으니 작은 우산을 챙기세요.
```

피해야 할 예:

```text
아까 알림이 틀렸어요.
```

## 아침 정기 추천 생성 흐름

1. 현재 시간 기준 알림 대상 사용자 조회
2. 사용자 프로필 조회
3. 집/직장 위치 조회
4. 기상청 API 호출 또는 캐시 조회
5. 출근/퇴근 시간대 날씨 분석
6. 옷차림 추천 생성
7. 추천 결과 저장
8. 알림 로그 생성

MVP 1차에서는 실제 푸시를 보내지 않고 알림 로그를 생성합니다.

## 날씨 변경 감지 흐름

MVP 1.5 또는 2차에서 구현합니다.

1. 아침 추천 결과 조회
2. 최신 날씨 예보 재조회
3. 기존 추천 결과와 새 추천 결과 비교
4. 추천 결과가 바뀌었는지 판단
5. 변경 알림 조건 확인
6. 하루 발송 횟수 확인
7. 변경 알림 로그 생성
8. 실제 푸시 발송
